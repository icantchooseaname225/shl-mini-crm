CHALLENGES FACED
================

I kept the project focused on the lead fields and actions from the task. One small setup issue was that the development environment included Node.js but did not expose npm as a command. I found the bundled pnpm package and used it to install dependencies, so I could keep the project in the existing workspace. One optional Netlify CLI dependency could not compile because Python for node-gyp was missing; it was not needed for this app, and the local function server, tests, and production build still ran.

As I simplified the project, I noticed Tailwind's build plugin was installed even though the dashboard used only regular CSS classes. I removed that unused dependency and kept the styles in one readable stylesheet.

I also needed to keep the database key away from the frontend. I made the browser call a same-origin /api/leads path and put all database operations in a Netlify Function. The Supabase server key is read only by that function, and the SQL schema enables row-level security without adding public policies. I used Supabase's newer secret key format and kept support for the legacy service_role key for compatibility.

For form validation, I added the same basic checks in the browser and the API. This helps users get quick feedback while ensuring the backend also rejects incomplete or invalid requests. I used a responsive desktop table and mobile lead cards so the contact details remain readable on smaller screens.

When I first ran the function through Netlify Dev, its current runtime passed a Fetch Request object instead of the older Lambda event shape I had used in my unit test. I updated the handler to accept both shapes, and then checked GET, POST, PATCH, DELETE, and invalid input through the local Netlify route.

I created a Supabase Free project, applied the schema, and checked that the seven sample rows and the RLS setting were present. I also checked the project with Supabase's security advisor and tightened the trigger function's search path.

The public GitHub repository is connected to Netlify's `main` branch and is live at https://shl-mini-crm-y9lc.netlify.app. The first build was blocked when Netlify's secret scanner matched the public Supabase project URL in `DATABASE_SETUP.txt`. I removed the literal URL and the next deployment succeeded. I then checked the live API by creating a temporary fictional lead, editing it and changing its status, and deleting it. The seven original sample leads were still there afterward.
