CHALLENGES FACED
================

One small setup problem was that Node.js was available in the workspace, but npm was not available as a command. I used the pnpm package that was already there to install and run the project. An optional Netlify CLI dependency also needed Python to build one of its tools. That part was not needed to run the app, so I kept going with the working setup.

I noticed that the project had a Tailwind build plugin even though the dashboard was using regular CSS. I removed the unused plugin and kept the styles in one stylesheet. That made the project a little simpler to understand and build.

I wanted to keep the database key away from the browser. The page now calls a Netlify Function, and that function talks to Supabase. The database has row-level security turned on and no public policies. I also added the same basic checks in the browser and in the function, so a bad form entry is rejected in both places.

When I first ran the function through Netlify Dev, the runtime sent a standard web request, but one of my tests expected the older Lambda event format. I changed the function so it can handle both formats. After that, the local GET, POST, PATCH, DELETE, and validation checks worked.

The first Netlify deploy was blocked because its secret scanner found the public Supabase project URL written in DATABASE_SETUP.txt. The URL itself is not a secret, but the scanner matched it against the configured environment value. I removed the literal URL from the document and the next deploy succeeded.

I also checked the live API with a temporary fictional lead. I added it, changed its business name and status, then deleted it. The seven sample leads were still there after the check. The live site is at https://shl-mini-crm-y9lc.netlify.app, and it deploys from GitHub's main branch.
