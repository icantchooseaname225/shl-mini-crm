MINI CRM DASHBOARD — DATABASE SETUP
===================================

I wrote this guide for someone setting up the database for the first time. The live website already uses a Supabase project with seven fictional leads. You do not need to follow this guide just to view or submit the live website.

If you want to create a separate database of your own, follow these steps.

1. Create a Supabase account
----------------------------

Go to https://supabase.com and create a free account. Follow the instructions on the site to verify your email and sign in.

2. Create a project
-------------------

In the Supabase dashboard, choose New project. Pick an organization, name the project shl-mini-crm, select a nearby region, and create a strong database password. Save the password somewhere private. Wait for Supabase to finish setting up the project.

3. Find the project URL and server key
--------------------------------------

Open the project, then go to Project Settings → API Keys.

- Copy the Project URL. It looks like https://your-project-id.supabase.co.
- In the Secret keys section, create or copy a key that starts with sb_secret_. This key is private and is only for server code.
- Do not use the Publishable key or the old anon key as the server key.
- Older Supabase projects may have a legacy service_role key. This project supports it under the name SUPABASE_SERVICE_ROLE_KEY, but the newer secret key is preferred.

Do not put a real key in this guide, GitHub, or the browser. The app sends the secret key to Supabase from the Netlify Function. More detail is in Supabase's API key guide: https://supabase.com/docs/guides/getting-started/api-keys.

4. Create the leads table
-------------------------

In Supabase, open SQL Editor and start a new query. In the GitHub repository, open database/schema.sql, copy the file contents, paste them into the SQL Editor, and run the query.

This creates the leads table, limits status to New, Contacted, or Converted, updates the updated_at field when a row changes, and turns on row-level security. The file does not add public database policies.

5. Add the sample leads
-----------------------

Start another SQL Editor query. Open database/seed.sql in GitHub, copy its contents, paste them into the editor, and run it once. It adds seven fictional leads with different statuses. Their email addresses use the reserved .test domain.

Do not run the seed file a second time on the same database unless you mean to add the sample leads again. The live database is already seeded.

6. Set up the project on your computer
--------------------------------------

In the project folder, copy .env.example and name the copy .env. Open .env in a text editor and replace the example values:

    SUPABASE_URL=https://your-project-id.supabase.co
    SUPABASE_SECRET_KEY=your-private-server-key

Use your own project's URL and secret key. Keep .env on your computer; Git ignores it so it should not be uploaded to GitHub. Do not add VITE_ to either variable name because VITE_ values are sent to the browser.

To start the site and API locally, open PowerShell or a terminal in the project folder and run:

    pnpm install
    pnpm dev

Open the local address printed in the terminal, usually http://localhost:8888. The README has the full beginner run-through.

7. Add the settings to Netlify
------------------------------

The live project is https://app.netlify.com/projects/shl-mini-crm-y9lc. In Netlify, open the project and choose Manage → Environment variables. Add these names:

- SUPABASE_URL: your Supabase Project URL.
- SUPABASE_SECRET_KEY: your private Supabase secret key.

Set the values for production and Functions. If you only have the older service_role key, use the name SUPABASE_SERVICE_ROLE_KEY instead. Save the settings and trigger a new deploy.

The live project already has its environment variables. These steps are only needed if you create a new Netlify project or replace a key. Never use a VITE_ name for the secret.

8. Check the database connection
--------------------------------

Open the website. It should show the seven sample leads and counts based on them. You can also run pnpm dev locally and check the address printed in the terminal. If the leads do not load, check that the project URL and secret key are correct, and that you ran both SQL files.

If Supabase has paused the project, open its dashboard and resume it. The current public demo has no sign-in, so only use fictional sample information. Anyone with the live site can change its demo leads.
